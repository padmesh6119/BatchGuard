# Synthetic scan dataset: what it can establish

For the separate synthetic traffic and IBM Z capacity test, see [IBM Z / LinuxONE scale](IBM_Z_SCALE.md).

BatchGuard has **no real pack-verification scan dataset or physical-pack provenance**. Its existing Layer B training and test episodes are generated by `src/simulator.py` from seven scripted families. The two held-out families are `delayed_sync` and `slow_copy`; the other five appear in training. The 231 original test episodes contain 99 generated positive episodes (42.9%). These results test code behavior on the specified scripts. They do not estimate clone prevalence, field precision, counterfeit detection, or medicine safety.

The original generator has an easy path to high scores: `clone_copy` creates the impossible-travel pattern used by the rule, and `clone_burst` creates the repeated-pack threshold used by the rule. Ordinary location, clock, and scanning errors are absent as negative cases. Pack IDs are distinct across train, validation, and test, but the same real reference product/batch can be drawn again; product and batch text are excluded from the scan model's features. The reference data gives realistic-looking names, **not** scan labels or a representative sampling frame.

## Frozen diagnostic challenge v1

`src/synthetic_challenge.py` creates [`challenge_v1.jsonl`](../data/synthetic/challenge_v1.jsonl) from a fixed seed. It uses entirely synthetic product and batch names. Each JSONL record has a case ID, a mechanism, valid `ScanEvent` payloads, and hidden `truth_events` with physical-pack identity and actual time/location. The `copied_id` label is derived from whether more than one physical pack maps to one observed pack ID. Hidden truth is never passed to the detector. A positive label does not mean a drug is counterfeit or chemically substandard.

The challenge has 100 examples of each of 11 mechanisms (1,100 cases): four copied-ID mechanisms and seven benign mechanisms. It is **deliberately mechanism-balanced, not a sample of field traffic**. The cases probe failure modes; repeated jittered templates do not make 1,100 independent real-world observations. We designed this challenge after inspecting the original generator and rule, so it is an exploratory stress test, not a blinded confirmatory evaluation.

| Copied-ID mechanism | Benign mechanism with the same detector features | Missing evidence |
|---|---|---|
| Fast copy across cities | Bad GPS location | Trusted location or physical-pack provenance |
| Slow copy across cities | Legitimate travel | Physical-pack provenance |
| Same-site copy | One pack scanned by two readers | Physical-pack provenance |
| Repeated copied ID | Repeated manual scans of one pack | Scan process or physical-pack provenance |

Each of those 400 positive/negative pairs has **identical values for all nine scan-model features**. An algorithm restricted to these fields must give each pair the same score. Better tuning alone cannot resolve that ambiguity.

The committed [`challenge_v1_report.json`](../data/synthetic/challenge_v1_report.json) evaluates the **existing frozen scikit-learn model and rule**, without fitting or choosing a new threshold on the challenge:

| Diagnostic set | Copied IDs flagged | Benign cases flagged | Missed copied IDs |
|---|---:|---:|---:|
| Declared rule | 200 / 400 | 300 / 700 | 200 / 400 |
| Existing trained model | 300 / 400 | 400 / 700 | 100 / 400 |

The model flags more copied-ID cases here but also flags more benign cases. The benchmark's precision (40% for the rule, 42.9% for the model) is **only the precision of this artificial mixture**. It must not be quoted as expected field precision. The reported model threshold and version are recorded in the JSON report.

Reproduce the dataset and report with `python -m src.synthetic_challenge`; use `--rule-only --output /tmp/batchguard-challenge` if trained artifacts are unavailable. The report includes the dataset SHA-256. `python -m unittest discover -s tests` checks deterministic generation, label separation, the ambiguous pairs, and the stored hash.

## What comes next

1. Keep challenge v1 fixed as a stress test. Do not tune the model or rule on it and then call its result held out.
2. Specify and collect the missing provenance and quality fields before making a physical-copy claim: a trusted pack identifier, authenticated scanner identity, server receipt time, clock status, location accuracy, and adjudicated reasons for repeated scans. Separate a suspicious scan pattern from an adjudicated copied identifier.
3. Build a broader training simulator from documented assumptions, then reserve unseen mechanisms and nuisance conditions for a new, separately generated test. Report sensitivity by mechanism and alert burden under explicit prevalence and error-rate assumptions; do not present assumed rates as measured ones.
4. Only real scan events with an independently adjudicated outcome can establish how often this helps or distracts inspectors in practice.
